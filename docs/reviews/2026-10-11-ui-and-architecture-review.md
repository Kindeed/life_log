# LifeLog 界面与架构优化评审

建议保留 Flutter 和现有本地优先架构，先统一保存反馈、状态标签、转场与暗色主题，再整理“更多”的全部入口。时间线与统计存在日期范围和币种问题，应与界面调整一起优先修复。性能方面值得重构的是跨功能查询与列表构建，目前没有整体更换框架会更快的依据。

评审基线为 `c619c98`，版本 `1.4.38+44`，日期为 2026 年 10 月 11 日。下方评审部分记录开始实施前的源码问题与建议；用户随后授权整理修复，实际改动与验收见本文末尾。用户提到的三张图片未随消息附上，因此具体截图的视觉定位仍需核对；原订阅源码没有“进行中”文字，该文字属于项目状态。

## 当前问题与优化方向

### 保存反馈

工时保存使用默认配色的浮动 SnackBar，持续 3 秒，没有设置紧凑宽度；订阅保存额外设置成功背景色，删除又使用默认颜色和不同持续时间。全局主题只约束浮动行为和胶囊圆角，因此“使用了同一种控件”仍然不能保证同一种视觉效果。

代码位置：`lib/features/work_log/presentation/add_log_sheet.dart:417`、`lib/features/subscription/presentation/add_subscription_sheet.dart:481`、`lib/common/theme/app_theme.dart:159`。追踪项：U356。

建议提供一个共享操作反馈接口，明确成功、信息、失败三个角色：

- 保存成功用紧凑、宽度受约束的提示，短文字不铺满整屏；默认可试验 1.8 至 2.2 秒，按文字长度与无障碍需求延长。位置避让导航、悬浮按钮、键盘和安全区。
- 保存时在当前按钮或表单显示进度，避免整页遮罩。失败保留表单、输入与重试入口；成功提示不承担错误恢复职责。
- 背景和文字用成对主题颜色，统一图标、间距、圆角、覆盖与去重规则。快速连续操作不让旧提示排队跨页出现；语音阅读器仍能获知结果。
- 删除只有存在真实撤销能力时才显示撤销操作，不能为了模仿其他应用承诺不可兑现的行为。

已有本地保存成功后立即反馈、云同步在后台继续的行为需要保留。U338 和 U339 解决的反馈缺失、被弹层遮挡及等待刷新问题不应重新引入。

### 状态与订阅信息

公共 `AppPill` 与凭证 `_MetaPill` 的圆角、字号、内边距和颜色透明度不同。订阅卡片又把暂停、取消、归档与下次扣费日期放在同一个文本位置。代码位置：`lib/common/widgets/app_pill.dart:23`、`lib/features/evidence/presentation/evidence_list_view.dart:475`、`lib/features/subscription/presentation/subscription_view.dart:588`。追踪项：U357。

建议统一状态标签的外观规格，保留业务语义。例如项目“进行中”、订阅“已暂停”和凭证“待报销”可以使用相同组件，各自显示正确状态。生命周期标签与“10 月 20 日扣费”分开表达；即将扣费才提升提醒强度，正常状态保持安静。

标签尺寸应由文字内容和字号决定，窄屏允许换行或移到下一行。纯展示标签可以紧凑；可点击的筛选和状态操作需要足够的触摸面积。不能将所有状态都改成“进行中”，也不能为视觉统一改变订阅周期计算。

### 转场与局部变化

同一个“更多”页的账户入口使用共享 `appPageRoute`，分组入口使用 `MaterialPageRoute`。共享路由为 240ms 淡入加 6% 横移，但忽略旧页面的 `secondaryAnimation`；弹层也混用显式 AppMotion 和默认时长。底部导航胶囊跟随页面进度，图标与文字却随目标索引立即切换。工时类型表单通过条件分支直接替换内容。

代码位置：`lib/features/more/presentation/more_view.dart:47` 与 `:404`、`lib/common/widgets/app_page_route.dart:7`、`lib/features/shell/presentation/tabs_view.dart:218` 与 `:263`、`lib/features/work_log/presentation/add_log_sheet.dart:189`。追踪项：U358、U359。

建议按交互用途建立运动规则，而不是给整个应用套一条曲线：

| 场景 | 运动方案 | 初始试验范围 |
| --- | --- | --- |
| 工时 项目 更多 | 页面与导航指示连续移动，图标前景同步插值；保留页面和滚动状态 | 点击切换 180 至 260ms；滑动跟随手势 |
| 列表进入详情 | 方向明确，前后页面适度联动，进入和返回各有收尾曲线 | 进入 200 至 260ms，退出 160 至 220ms |
| 编辑弹层 | 内容、遮罩与键盘协调，关闭从当前进度继续 | 进入 240 至 300ms，退出 180 至 240ms |
| 状态 筛选 表单类型 | 只过渡变化区域，保留草稿和焦点，不重播整页入场 | 120 至 180ms |
| 按压 保存确认 | 立即回应，轻微视觉变化，成功后自然恢复 | 90 至 140ms |

这些是设计试验值，需要依据真实体验调整。共享导航可通过主题及统一 route/page factory 实现，无需先把所有页面迁入一种新路由架构。系统返回、Android 预测性返回、快速反向点击和减少动画设置必须纳入契约；自定义效果不能削弱平台操作。

工时编辑、凭证编辑等已有未保存草稿保护，因此不能为了顺滑无条件开放拖动关闭。局部 AnimatedSwitcher 或尺寸动画也必须保留输入状态、焦点、校验信息和异步保存生命周期。

### 暗色主题

现有主题已有浅深色配对，但业务状态、图片占位和部分表单选中面仍绕过主题。`LogColors.work` 固定蓝色，而 `semanticColors.work` 随主题 primary 改变；凭证直接使用原始绿蓝橙色；工时下拉层和选中面使用固定暗色常量。

代码位置：`lib/common/theme/app_theme.dart:40`、`lib/common/theme/custom_colors.dart:70`、`lib/features/evidence/presentation/evidence_list_view.dart:402`、`lib/features/photo/presentation/photo_view.dart:640`、`lib/features/work_log/presentation/add_log_sheet.dart:303` 与 `:713`。追踪项：U360。

按默认源码配色进行 sRGB 透明度合成计算，非选中、非今日、非跨月的暗色工时“工”小字，对比约为 3.08:1：`#007AFF` 文字落在同色 20% 叠加于 `#212621` 的底色上。浅色凭证“已报销”约为 2.53:1：`#4CAF50` 文字落在同色 10% 叠加于白色的底色上。这两组低于小字常用的 4.5:1 验收线。计算只覆盖指定默认组合，动态主题与截图像素应分别核对。

暗色方案应重新组织背景、内容卡和抬升弹层三个表面层级，以文字、间距和少量分隔组织信息。状态色采用独立 foreground/container 配对，避免“同一个高饱和颜色兼作文字与透明底色”。图片占位、禁用面、选中面回归统一角色。

目前的 30px 卡片、28px 分组、22px 控件、36px 弹层是历史视觉基线。可试验更适合紧凑列表与设置行的角色尺寸，先在主题 token 和 UI 契约中定案，再应用到页面。无需让所有容器共享巨大圆角，也不宜逐页塞入新的硬编码值。暗色布局是否过松、边框是否过多，应以实际页面图确认。

## 更多栏目的完整整理

目前有八个目的地：账户、全部记录、统计、订阅、遥测计算器、外观、数据备份恢复、关于。账户页还承载同步状态和开发者诊断。现有功能去重已经做过，但账户按钮与账户卡仍重复，目录标题、内页标题和摘要范围也有差异。

建议保持三个主栏目，在“更多”中采用下面的顺序：

| 区域 | 入口 | 页面整理要点 |
| --- | --- | --- |
| 顶部账户摘要 | 账户与同步 | 只留一个入口，摘要显示账号或本地模式；登录、退出、手动同步与冲突处理集中在内页 |
| 记录与分析 | 全部记录 | 跨类型历史查询；统一日期范围、筛选、排序和编辑；区分失败、空数据和部分失败 |
| 记录与分析 | 订阅管理 | 管理周期、金额与状态；明确原币种金额和人民币估算，状态与扣费提醒分层 |
| 记录与分析 | 统计 | 统一月选择、金额口径和更新状态；支出与凭证分开，混合币种不直接相加 |
| 应用设置 | 外观 | 主题模式、动态取色、照片信息偏好；所有设置行共用规格，改变主题时给出真实预览 |
| 应用设置 | 数据与备份 | 导出与恢复；清楚说明当前备份仅数据库，照片和凭证文件不在包内；保留覆盖确认 |
| 应用设置 | 关于 | 版本与应用说明；提供诊断入口；开源说明有真实内容后再写入摘要 |
| 专业工具 | 遥测计算器 | 保留全部计算和知识功能，统一搜索、输入、结果、模板保存与错误反馈 |

“全部记录”内的分类应继续按同一种浏览规则展示，不应在筛选时换成一套拥有另一种标题、动作和状态的完整管理页面。订阅独立管理入口仍保留；时间线中的订阅分类重点用于检索及打开同一编辑入口。新增动作可由明确的记录类型选择提供，避免每个分类发明自己的保存路径。

设置列表统一图标尺寸、文字层级、箭头、分隔线、边距、按压反馈和窄屏换行。摘要只保留影响选择的信息，减少每行都带长宣传式描述。开发者诊断可放在关于内，账户页聚焦账号与同步；日志与诊断仍需容易找到。

追踪项 U361、U363。源文件包括 `more_view.dart`、`profile_view.dart`、`appearance_view.dart`、`data_management_view.dart`、`about_view.dart` 和 `telemetry_calc_view.dart` 的各 presentation 实现。

## 需要优先修复的功能问题

### 全部记录的日期范围

`timeline_view.dart:136` 创建月历用的 WorkLogCubit，其初始聚焦今天并调用当前月查询。`:248` 仅展平这个月的工时；支出、凭证和订阅来自完整集合。因而入口叫“全部记录”，不同类型的实际历史范围却不一致。追踪项 D84。

建议建立所有类型共用的日期范围与分页规则，默认浏览近期记录并能继续加载历史。不能仅把标题改成“本月”而继续显示其他类型的全历史；也不能为了简化显示删除同日多条工时。

### 币种展示与统计

`formatMoney` 固定前缀 `¥`。时间线支出与凭证、支出分类列表、凭证列表调用它时没有传入原币种。USD 100 因此会呈现为 ¥100。追踪项 D85。

`ExpenseRecordEntryStats.totalAmount` 和凭证金额统计直接相加，不按币种分组；`statistics_controller.dart:354` 再把支出和已折算人民币的订阅额相加。追踪项 D86。

优先按原币种显示及分别汇总。若增加人民币估算，必须明确汇率日期、来源和缺失状态，并与原金额区分。例如 CNY 100 和 USD 100 不能显示为总支出 ¥200。凭证报销统计同样按币种处理，支出与凭证保持独立，不推测两者对应关系。

### 支出分类的操作与失败

`timeline_view.dart:414` 的支出分类只判断加载和空集合，读取失败也会显示“暂无支出记录”。`:468` 的行没有编辑动作，但同一记录在“全部”视图可编辑，分类中也没有新增入口。追踪项 D87、U363。

建议统一编辑路径、提供合适的新增入口，首次失败显示重试，带缓存的失败保留记录与可见错误。用户不应切回“全部”才能修改已经找到的一笔支出。

## Telegram 动画的参考机制

本轮读取 Telegram Android 的固定提交 `f2908b14133bbffbf7ab04f641ecb5bfaf533242`。以下依据实际实现，不将不同平台或历史版本的一种效果说成 Telegram 的全局规则：

- [ActionBarLayout.java](https://github.com/DrKLO/Telegram/blob/f2908b14133bbffbf7ab04f641ecb5bfaf533242/TMessagesProj/src/main/java/org/telegram/ui/ActionBar/ActionBarLayout.java#L1608) 在手势收尾中依据剩余距离计算时长，并设置不同最低时长；预测性返回采用独立策略。前后容器参与推进、返回和拖动。LifeLog 可借鉴从当前进度继续和前后页面连续反馈。
- [CubicBezierInterpolator.java](https://github.com/DrKLO/Telegram/blob/f2908b14133bbffbf7ab04f641ecb5bfaf533242/TMessagesProj/src/main/java/org/telegram/ui/Components/CubicBezierInterpolator.java#L13) 提供 `EASE_OUT_QUINT` 的控制点 `(0.23, 1, 0.32, 1)`，同时存在其他曲线。可在详情与弹层候选场景试验，避免全应用使用同一种弹簧。
- [BottomSheet.java](https://github.com/DrKLO/Telegram/blob/f2908b14133bbffbf7ab04f641ecb5bfaf533242/TMessagesProj/src/main/java/org/telegram/ui/ActionBar/BottomSheet.java#L701) 取消旧键盘内容动画，并使用键盘的时间和插值器；弹层进入、退出与遮罩有各自协同策略。LifeLog 应重点处理打开键盘途中返回、快速关闭与重复触发。

值得学习的是即时反馈、可打断的连续运动、手势与键盘协调，以及资源准备和渲染成本控制。具体效果应在现有 Flutter 组件中独立实现，不需要引入 Telegram 的协议、原生导航框架或整个技术栈。

## 框架与性能调整

现有 Flutter、GoRouter、GetIt、Cubit 和 ChangeNotifier 已能表达上述界面。Cubit 适合功能工作流，轻量 listenable 适合主题和局部状态；混用本身不能证明慢。GetStorage 是持久化，当前生产实现没有 GetX 运行时状态或路由。Isar 是本地数据源，Supabase 仍是可选同步。

整体换框架会增加数据兼容与迁移验证、设备集成、测试与发布成本，当前没有基准证明这些成本换来收益。建议在现有架构中逐步完成下面的调整：

1. **共享界面契约。** 将操作反馈、状态颜色、设置行和页面弹层运动集中到公共层。明确控件用途与状态，减少各 feature 自行组合参数。
2. **跨功能查询。** 时间线目前在四层 BlocBuilder 中全量映射、合并和排序，并在 ListView.children 中预先创建全部行。增加独立应用查询模型，明确 owner、日期、项目、类型与分页，将 UI 层改为消费统一快照。先使用现有 repository 接口；数据层优化单独验证。
3. **惰性构建与缓存。** 使用稳定标识和按可见区域创建的行，缓存与当前范围有关的派生结果。不要因改变一次筛选重建所有历史 Widget；保留滚动和已加载内容。追踪项 U362。
4. **统计范围。** 当前统计读取完整集合后按月计算。先修正币种与数据口径，再测大数据量成本；必要时增加范围查询及按月份和币种的聚合。保留统计按来源合并刷新，以及各 feature Cubit 已有的旧读取结果保护。
5. **启动与后台生命周期。** `lifelog_mobile_entry.dart:66` 在 runApp 前依次等待本地初始化和可选云初始化，值得记录分段耗时。只有测出瓶颈后才拆分；本地数据可用与账户范围正确是前提。统计和保活页监听也应按实际后台读取成本评估。

查询范围需要区分本地可见性与上传资格：本地列表可包含当前账户及未归属的本地记录，云上传仍严格限定当前认证 owner，不能复用一个筛选条件处理两种职责。

文件大或层次多是维护成本信号，不能单独证明帧率低。不要为减少目录数量删除正在使用的兼容适配器；也不要为“换更快框架”顺带更换数据库或同步协议。

## 分阶段实施与验收

| 阶段 | 交付重点 | 完成标准 |
| --- | --- | --- |
| 第一阶段 | 保存反馈、状态标签、暗色颜色；先修币种展示、混合汇总与失败伪装为空 | 真实工时与订阅编辑、凭证列表通过浅深色和大字体检查；保存时序、原始金额和错误恢复保持正确 |
| 第二阶段 | 更多全部入口、共享设置行、标题及动作一致 | 八个目的地逐项可达；备份范围说明准确；分类记录可编辑及新增；账号与诊断能力保留 |
| 第三阶段 | 统一导航、弹层、Tab 和局部表单动效 | 快速点击、反向切换、返回、键盘与减少动画均连贯；草稿、焦点及滚动状态保持 |
| 第四阶段 | 历史查询、范围与分页、懒构建、统计和启动热点 | 历史月份可检索；记录读取及构建数量有证据；同设备 profile/release 比较显示实际收益 |

跨月历史范围属于第一轮应确立的查询契约；其完整分页实现可与第四阶段一起完成，不应在前面阶段继续把不完整列表当作全历史验收。

UI 验证覆盖 320dp 和 390dp、正常及两倍中文字号、浅深色、动态配色、长名称、缺失图片、长提示、键盘和安全区。状态文字需要检验对比度与语音阅读器语义；页面截图不能只检查没有 overflow，还要检查对齐、密度和实际可读性。

性能采用同一设备的 profile/release 数据，分别记录冷暖缓存、图片尺寸、数据规模和样本数。沿用 ADR 0002 的目标：10k 工时、100 项目、5k 照片和 5k 支出凭证元数据；非文件本地保存 p95 不超过 300ms、项目首个内容 p95 不超过 500ms、冷启动可交互不超过 2 秒、60Hz 滚动超预算帧低于 1%。120Hz 场景按对应帧预算单独记录。这些仍是目标值，不能当作已经达到的成绩。
