# 项目详情：整体结构与逻辑优化

审查日期：2026-10-07。基线：v1.4.36。依据：用户提供的深色项目详情截图，以及页面、数据边界和相关测试的联合检查。

## 审查结论

上一轮只限制了照片网格的解码尺寸，没有重整这个页面的信息结构。截图中的大图标页签、同名筛选与底部三按钮同时争夺注意力；照片动态没有图片，费用和凭证的关系也没有讲清楚。

这次统一采用 LifeLog 已有的暖中性色、绿色主色、柔和圆角和主题配对。借鉴 Telegram 的紧凑导航、按时间阅读、按场景展示操作；此前固定提交的源码参考见 [Telegram 源码审查](2026-10-07-telegram-source-optimization.md)。这里不宣称复现 Telegram 后端，也不宣称已经实机体验 Muse。

## 一个项目，三个阅读任务

| 入口 | 用户要解决的问题 | 展示内容 | 操作 |
| --- | --- | --- | --- |
| 动态 | 项目最近发生了什么 | 按日期分组的照片、支出、凭证、关联出差 | 单一类型筛选入口；打开原记录 |
| 照片 | 找到并查看现场照片 | 本地缩略图网格 | 原图预览、长按／批量选择、确认删除、导出 |
| 账目 | 看实际支出与报销材料 | 分币种支出汇总、支出明细、独立凭证区 | 编辑支出、查看凭证与原有报销状态 |

顶部改为紧凑文字页签。动态筛选收进一个菜单；“费用”只筛支出，“凭证”单独筛材料，不再混合两类记录。底部保留一个“添加记录”，再选择照片、支出或凭证；沿用原有操作流程，并预选当前项目。

项目节点移到独立的横向信息行，保留完整内容，避免挤占标题。卡片、导航、主按钮和按压反馈复用共享组件；大字体时记录内容纵向重排。动态显示受尺寸限制的照片缩略图，全屏仍使用原图。动态和账目按需创建可见记录控件，各自保留滚动位置。

## 账目口径

- **已记录支出**只汇总支出记录，按原币种分别显示。
- 凭证是证明材料，拥有自己的金额与状态。现有模型没有逐笔支出结算关系，不能用已报销凭证扣减支出，也不能把两者相加制造第二份支出。
- 普通支出没有独立报销状态，因此不再把每笔普通支出自动标成“待报销”。
- 凭证区继续显示“待报销／已提交／已报销”；未填写金额显示“金额未填写”，不伪装成零元。
- 出差金额与报销情况保留在出差动态和编辑页，不再次加入支出明细汇总。
- 不推测凭证与支出的重复关系，不引入汇率转换，不改写任何历史金额或同日多条工时记录。

## 数据与操作

明确传入项目 id 时，标题先按 id 查找。记录归属优先匹配项目同步关联，其次本地 id；只有没有关联标识的旧记录才按名称回退。明确关联到其他项目的记录不能仅因同名而混入。

费用直接来自 ExpenseRecordCubit 的最新本地状态，删除独立且容易过期的 repository 快照。出差通过既有应用层读取，监听工时变化、合并连续通知，并拒绝旧成功或旧失败覆盖新结果。项目范围改变时清除旧出差快照。

从项目列表进入详情时，传入已经加载的项目、照片、支出、凭证 Cubit，不再额外创建四套监听及初始读取。详情借用这些状态，返回时不关闭父页面的数据源；独立路由仍可创建并管理自己的状态。

下拉刷新并行读取本地数据。读取失败保留已加载内容，展示明确的重试提示；加载中、真正空项目、筛选无结果和部分失败分别处理。出差卡片现在能打开原记录编辑页。

批量照片操作显示处理中，阻止重复操作；不可用或失败时保留选择并反馈错误，成功立即反馈。导出文案说明“所选文件夹”，不再误称“相册”。本地列表更新后清除已不存在的选择 id。

修改项目节点、归档或取消归档时保留封面路径，避免无关操作清空封面设置。费用过滤每次捕获一个项目范围，避免逐条费用重复查找项目。

照片保持本地；不修改数据库模型、云同步版本／墓碑／账号规则、生产迁移或备份流程。
