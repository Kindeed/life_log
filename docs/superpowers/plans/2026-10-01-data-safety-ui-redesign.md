# LifeLog 数据安全修复与界面优化方案

日期：2026-10-01。审查基线：`503a7e4`。状态：方案与交互样稿已完成，修复和 Flutter 界面落地尚未实施。

这次改造解决当前审查中的 9 项缺陷，并按用户选择的「精致柔和：留白、圆角、细腻层次」优化日常操作。先恢复账号隔离、同步与备份的数据安全保证，再完成关键界面的设计和迁移；每批有独立验收，避免将数据库变更、同步协议和所有页面同时替换。

## 已确定的方向

- 保持「工时 / 项目 / 更多」三入口，默认工时；订阅、统计、凭证和工具继续保留。
- 界面采用暖白背景、轻量分组、柔和圆角和低饱和青绿色强调。深色采用暖灰黑与较亮的青绿色，颜色配对统一管理。
- Telegram 作为清晰列表、直接反馈与过渡手感的交互参考；大模型应用作为克制排版和阅读层级的参考。这些是设计取向，尚未做相关产品的逐屏对比。
- 用户补充 Muse 是 Meta 的机器人手机 App；具体产品链接和界面仍未核对，不将猜测作为视觉规范。后续得到链接后核对字号、间距和动效，不复制品牌资产。
- 照片始终仅本地保存；同日多类工时记录必须保留；媒体缺失、读取失败与真正空数据分别呈现。
- 所有现有用户修改保留。不执行远端迁移、不推送、不发布、不安装设备。

## 关键接口设计

### 同步身份与回写

`SyncRunContext(ownerId, sessionEpoch, runId, databaseGeneration)` 随请求传递到适配器和数据库事务。事务开始及提交前检查 context；检查通过才读取或修改对应 owner 的数据。拉取必须验证行的 user_id。旧运行只能清理自己的资源，不能复用新账号的当前状态。

`PushSnapshot(syncId, mutationRevision, baseRemoteVersion, operation)` 明确说明本次上传的是哪次本地变更。远端成功后调用 `acknowledge(snapshot, remoteResult, context)`；方法重新读取行，不持久化传入的旧对象。若 revision 已变化，更新可适用的远端身份/版本并保留待同步状态。删除需要匹配具体 tombstone 的 ACK，不能因整次 sync 返回 true 就任意物理清除。

已存在 remoteVersion 可暂作编辑基准；未解决的拉取版本和字段保存在独立冲突快照中。需要同时明确本地 revision、远端 currentVersion 和编辑 baseVersion 的区别。先用订阅完成纵向测试，再迁移工时、项目、支出、凭证；凭证附件单独保持上传/删除状态协议。

队列键须包含 owner，不依赖 localId 的跨设备含义。旧 hash 队列无法可靠反推出业务实体：迁移时保留诊断证据并重新枚举实际 pending 记录，不将旧记录猜测映射到其他账号，也不据此丢弃业务变更。

### 恢复生命周期

明确 `prepare → validate → quiesce → snapshot → replace → rebind → refresh → verify → complete` 状态，任何失败进入可恢复路径。`snapshot` 在写入已停止后生成；候选校验在独立路径和实例上完成，不覆盖当前数据库来测试文件有效性。

数据库拥有者统一维护 generation 与消费者重建，不能只调用 DbService.init 或导航到首页。消费者包括注册的 IsarDatabase、同步队列、同步中心存储、页面 Cubit、统计及所有 watcher。恢复期间命令得到明确的繁忙状态，旧 epoch/generation 的异步结果不可提交。

游标在 GetStorage 中，数据库在 Isar 中，不能假设二者拥有共同事务。恢复状态日志持久化 full-refresh-required；启动时未完成的恢复也执行修复流程。有效恢复完成前保留原快照；回滚失败返回 recoverablePath 和独立错误，不在 finally 中删除唯一恢复副本。数据库备份仍明确不包含媒体文件本体。

### 冲突选择

冲突快照按 owner、实体身份、operation 与版本保存；界面应展示用户可理解的字段差异。采用远端必须在事务中应用远端业务字段；复制生成新 syncId，保留项目关系且不复制远端身份；凭证文件复用或复制策略独立验证。所有操作都先验证当前账号和最新远端版本，禁止无条件覆盖。

## 视觉设计规范

交互样稿：`docs/ui/prototypes/2026-10-01-soft-lifelog.html`。打开后可以切换工时、项目、更多与深色，选择日期，进入项目详情，打开编辑弹窗并试用保存。内容全部是示例数据，刷新会恢复，不连接数据库或网络。

### 视觉层级

- 页面底色暖白 `#f6f5f1`，主要表面 `#ffffff`，强调青绿 `#426b5a`，正文石墨 `#242923`。这些是初稿，Flutter 实现使用 ColorScheme 与 semantic tokens，并保留动态配色前景/背景配对。
- 页面左右间距 20–24dp；页间结构留白 24–32dp，关联信息间距 8–12dp。列表靠字级与分组建立关系，不给每个统计量套卡片。
- 页面标题 26–28sp，正文 15–17sp，辅助 12–13sp，核心数字 34–38sp；中文与数字统一 baseline，金额使用等宽数字。所有文字尊重系统缩放。
- 根据用户对第一版「不够圆润」的反馈，摘要/项目表面圆角增至 30dp，普通分组 28dp，输入及类型选择 22dp；操作、状态标签、周/月切换使用胶囊轮廓，图标底座使用圆形，弹窗顶部 36dp。统一使用圆角令牌；阴影只用于悬浮操作、弹窗和真正浮起的内容，暗色以表面差异建立层次。
- 单屏一个明显主操作；常驻删除按钮收进明确菜单，删除前展示具体记录确认。列表操作仍有可发现的显式入口。

用户指出第一版日历的信息比原界面少。设计验收新增明确约束：不能用小圆点代替原有农历、节气、节日、班休、工作/出差/请假/休息与加班时长。日期格保留三层结构，工时状态不能遮掉同日节气；多条记录显示主要状态与额外条数，点击后列出所有记录。选中日期的完整农历、星期和节日/节气在详情区可读。窄屏允许垂直滚动，不靠隐藏信息保持首屏高度；主要操作不能盖住日期。

HTML 样稿农历由浏览器 Chinese-calendar Intl 格式化，节气、节日和调休标注使用声明过的布局夹具。正式 Flutter 继续通过现有 Lunar/HolidayUtil 和 WorkLogDayMetadata 获取信息，不将样稿里的节假日映射作为产品数据。

### 动效与流畅度

- 点击反馈 100–140ms；选中和筛选 160–200ms；页面切换 220–260ms；底部弹窗 260–320ms。先沿用 AppMotion 的集中入口，新增令牌时解释使用场景。
- 减少不相关元素一起运动。更新局部文字或列表项，避免整页淡出、重建与弹跳。日期和类型选中共享平滑指示器。
- 返回时保持列表位置、筛选和日期。保留上一版已读取内容，局部显示刷新或失败，不突然清空页面。
- 尊重减少动态效果设置；同一操作的手势、按钮、键盘反馈一致。触控至少 48dp，主按钮需明确焦点与语义标签。
- Flutter 性能验收在同一 Android 设备的 profile/release 模式测量。60Hz 帧预算 16.7ms、120Hz 8.3ms；长列表/图片要懒加载与适当解码。滚动超预算帧 <1% 是目标，不是当前结果。

## 验证与发布门槛

环境当前没有 Flutter/Dart；上次下载因代理连接失败而未完成。先恢复工具链并检查当前环境网络策略，不能将静态检查当作功能测试。样稿使用本机 Chromium 检查布局、交互、浅深色和窄屏；HTML 测试不能代替 Flutter 的 Android 运行表现。

测试重点是可导致数据丢失或串号的交错，而非仅匹配源码字符串：延迟 ACK、退出/切换账号、dirty v1 对 remote v2、编辑中删除、重复提交、队列重建、恢复中后台返回、恢复与回滚双失败。所有 schema 修改集中一批，生成 .g.dart 并核对迁移重跑和数据数量、金额、关联。

每批运行相关行为测试；交付行为改动前运行完整 flutter test、严格 analyze、只读 format 检查及 Debug build。最终在 Android 验证大字、TalkBack、键盘、文件选择与相机恢复、滚动帧时间。没有设备时明确标为未验证。

需要新增本地 mutationRevision/恢复日志字段时采用可加式迁移，先用匿名记录、双账号、旧版本、tombstone、缺失文件和多条同日记录做快照夹具。任何回退都先保留升级后的增量，不能直接降级改过的数据库。远端若需纠正 SQL，只新增 corrective migration；应用生产前单独安排审核。

验收完成后逐项更新 BUG_TRACKER 状态。目前 D13、D41、D43–D48、T31 均继续 open；本方案和样稿不构成这些缺陷已修复的证据。
